## Outcome and scope

FAQ search has a persistent label and a programmatic results relationship. Category buttons expose actual pressed/disabled states, and result counts use a polite status. Native `details`/`summary` disclosures retain keyboard operation and default-category answer access without JavaScript; each question controls a persistent answer target. Chromium's full accessibility tree reports the native disclosure name, expanded state and controls relation. Category/search filtering still requires JavaScript; complete FAQ content/schema/no-JS category parity remains B23.

Utility code has a named expand/collapse control, current expanded state and a labelled, focusable code region with a visible scroll hint. Keyboard scrolling reaches the full example at narrow widths and without JavaScript. Without JavaScript the height toggle does not operate, but the entire example remains scrollable; no interactive-toggle fallback certification is claimed.

All **23** original direct-main candidates now have native, focusable `main-content` targets. The design preview is distinguished as an internal no-shell route; no public header was added to it. SkipLink is a native anchor with no client wrapper/fallback handler. Shared scroll padding/margins keep tested focus below the sticky header, and consumer focus outlines remain visible where protected primitives use translucent rings. Existing PrimaryCTA/server primitives/legal renderer and Radix behavior were retained.

Header uses the existing Radix Sheet below 1280px, eliminating the verified 1024px overflow (baseline **1087px**, final **1024px**). Its short-height menu uses an inner scrolling navigation area and a separate footer in normal flex flow, with focus containment, Escape restoration and 44px menu/close targets. Contact details wrap without losing phone/email/hours content, eliminating the verified 320px overflow (baseline **334px**, final **320px**).

Tool/filter consumers expose selected states and persistent names: QR type/color/size/Wi-Fi controls; cost country, number fields and sliders; Blog search/clear/categories; flow categories and Coins choices. Existing protected Slider does not forward a consumer name to its thumb, so QR/cost consume the installed Radix Slider directly at those two existing islands, preserving keyboard value updates and adding named 24px thumbs. No protected UI file was edited. The country pricing table remains an inner keyboard region.

The **32** explicit blue/indigo utility occurrences in ten inventoried source files were replaced with existing brand or functional info tokens. ERP branding remains distinct from informational/Support styling; existing labels/icons continue to communicate meaning. Affected legacy opaque guide/tool/filter fills and white-text gradient panels use darker paired colors. A real contact validation error measured **4.41:1** on its pale error background; light-theme error/destructive tokens now use `#B91C1C`, and the actual validation error measures **5.91:1**. Dark error tokens and the brand identity color were preserved. Forced-color browser/system colors are respected rather than overridden with a brand palette.

Native Partner/Coins/Miracle FAQ decorations are aria-hidden so accessible names contain the question rather than an extra “+”. Their native keyboard/AX states were checked. Their factual answers and schema definitions were not rewritten or approved.
