## Final behavior and reader impact

The Link tool accepts supported international numbers: optional leading `+`, nonzero first digit, 7–15 ASCII digits. It rejects spaces, punctuation, extensions and lossy cleanup. Messages retain URL encoding. Invalid input produces a visible error; valid generation is local and does not establish WhatsApp availability or send anything. Phone/message edits clear stale output and controls, including pending clipboard results. Copy failures leave named selectable content and manual recovery. Share cancellation and external-open requests have honest status. Query navigation to QR carries the current encoded link; back restores a usable tool.

QR payload validation occurs before constructing the wrapper. Arbitrary text is distinct from navigation. HTTP(S) URLs permit a supported bare dotted hostname normalized to HTTPS, reject other protocols, spaces and embedded login; the supported host grammar is conservative. Phone/WhatsApp use the same international grammar. Email accepts one supported address with optional encoded subject. WiFi requires SSID/security/password rules and escapes backslash, semicolon, comma, colon and quotation marks. SSIDs are bounded by UTF-8 byte length; WPA/WEP/open security rules are explicit and open networks omit a password. Only fake WiFi fixtures were used; no raw password payload or WiFi QR image is published in evidence logs.

Every content/type/color/size edit invalidates the canvas and output controls. Generation renders to a detached canvas and commits only for the current input version. Async import, blob creation and clipboard completion cannot announce or download a superseded output. PNG is the only public export promise. Dynamic QR import/canvas stays local; import, unsupported clipboard, denied clipboard, null blob, blocked download and excessive density have visible retry/manual-download recovery. A download request is never labelled as a saved file. Color input requires six-digit hex, dark-on-light contrast at least 4.5:1, integer size 128–512, quiet zone four modules and minimum two rendered pixels per module. These are technical safety checks, not physical-scanner approval.

ROI starts with blank user assumptions, without invented currency, default accuracy or outcome claims. Blank/nonfinite/negative/fractional counts, unsupported numeric syntax, unsafe precision and overflow yield explicit unavailable results. Costs may be nonnegative decimal values; qualification rates are 0–100. A 0% rate produces zero qualified leads. Cost-per-zero and other zero denominators are unavailable; savings and ROI can be negative. Qualified-lead comparison uses the intended baseline denominator. Visible method/FAQ and matching schema explain the user scenario. The server page owns article/heading/method; only calculation controls/results require a client island.

Shared message inputs on `/pricing` and the free cost tool retain raw drafts, distinguish blank/invalid from zero, require finite integer counts within the existing UI limit and label errors. Coin quantities/balance do the same with the inherited bound. The source calculators preserve valid central plan/GST/rounding/coin arithmetic, but malformed public inputs no longer become invented zero estimates. Two inherited tests were strengthened from invalid-input zero to unavailable. B12 current money/rates/conversion/recharge/entitlement remain withheld. Existing bounds are explicitly input limits pending OI03, not approved wallet/volume entitlements.

Plans, partners and coins retain named focusable inner table scrollers; visible hints describe arrow-key navigation. Actual keyboard scrolling reaches the last column at all five widths. Checkout query parsing, disabled payment and native selection behavior are unchanged and rechecked, including blank/repeated/unknown query values. A selection does not create an order or activation.
